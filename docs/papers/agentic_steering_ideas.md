# Agentic steering：原始候选方向与讨论

这是一份研究讨论记录，保存 Claude 提出的候选方向、随后的评估，以及重新组织的三条主线。它不是实验方案，也不意味着已经选定课题。原始候选中的新颖性判断保留为讨论材料，不作为完成文献检索后的结论。

相关入口：[完整候选问题与测量表](agentic_steering_candidates.md)、[文献方向评估](research_directions.md)、[论文阅读入口](README.md)。本文不修改论文的 Contributions、Limitation 或用户 Additional think，也不参与 CSV／Excel 同步。

## 讨论的出发点

用户希望共同从 agent 研究和 LLM behavior 出发：先理解 agent 的实际需求与失败过程，再研究表示和 steering 可以提供什么控制。例如 drift 对持续执行的影响、reward hacking 对目标优化的影响。保留两种合理起点：需求驱动，以及有价值的行为现象驱动；不要求每个研究一开始就提出新 controller 或完整机制。

坐标系可以整理实验：控制对象 × 方向来源 × 提取位置 × 注入位置 × 算子 × 评价终点。但这些维度在实际系统中未必独立。换一个格子能产生实验，不自动产生重要的研究问题。

## Claude 原始候选方向

以下保留原始方向的标题、问题、做法和主张。为便于回看，删除了开场与过渡句；新颖性断言在后文单独评估。

### 1. 因果阶梯：读得出 ≠ 推得动 ≠ 整条轨迹变好

- 问题：同一组向量，在三级终点上是否一致？① probe 能读出；②干预能改变下一步动作；③闭环全程干预能改善轨迹和任务成功。
- 原始空间判断：ContextEcho 的附录只是局部证据（投影恢复了，表达没恢复）。TACT 和 reward hacking 那篇做了闭环，但目标是失败模式，不是 persona。没人系统地在多个 persona/behavior 方向上把这三级对齐比较。
- 做法：固定一批方向，在同一批任务上分别测 snapshot probe、单步动作分布变化、全程 closed-loop。重点量化 replay 和 closed-loop 的差距（反馈分布偏移）。
- 产出：偏测量与方法论，不依赖发明新算子。风险是闭环 rollout 工程量。

### 2. 面向 agent 的行为型 persona 分类

- 问题：Big Five 是为人类设计的，对 agent 未必是好的坐标系。影响成败的“人格”可能是验证倾向、坚持 vs 放弃、主动性 vs 听从、风险偏好、探索 vs 利用、反馈采纳度。
- 做法：从带行为标签的轨迹提取这些轴，与 Big Five、VAD emotion 方向做几何和功能对照。例如 conscientiousness 与验证倾向，dominance 与决策果断。
- 关键检验：表示重叠不等于功能等价，要看 steering 后的行为是否对应。
- 价值：回答 agentic 场景下 persona 空间应如何划分。

### 3. 提取位置 × 注入位置的迁移矩阵

- 问题：planning、thinking 结束、tool call 前、反馈后提取的方向，在其他位置注入是否有效？E-STEER 发现阶段偏好的情绪区域不同，但未系统比较分阶段提取。
- 做法：K 个提取位置 × K 个注入位置。观察对角线是否占优、通用方向是否存在，以及哪些位置更敏感。
- 产出：在哪里干预性价比最高的经验规律。

### 4. 为什么投影恢复了、表达没恢复：drift 的机制

- 问题：如果 Axis 投影拉回而输出不变，表达是否走其他路径？候选解释包括多层冗余、attention 读取历史、KV cache 中的上下文影响。
- 做法：逐层／逐 head 因果实验，比较 residual、attention output、KV 干预，以及单向量与子空间。区分表达 drift 和行为 drift，检验前者是否导致任务行为变化。
- 价值：从现象走向机制，解释 steering 失效。

### 5. 真正的在线方向更新

- 问题：目前多是离线提取、运行时调强度。原始主张认为当前 episode 真正更新方向的只有 ATLAS state 子空间，且它不是行为方向。
- 做法：比较离线固定、在线调强度、在线更新方向。候选信号包括窗口内 judge 标注、同状态下带／不带指令的激活差、环境失败反馈。
- 风险：干预改变分布，方向随之变化，进一步改变干预；可能形成不稳定反馈。

### 6. 通用的监控＋控制闭环：read/write 分离

- 问题：DRAS、TACT 针对单一失败模式定制检测和强度调节，能否抽象为通用 controller？
- 研究点：detector 校准、干预后分布外泛化，规则／bandit／小策略网络选强度，多种风险触发时的仲裁。
- 价值：把零散工作统一为框架。

### 7. 多向量组合与干扰

- 问题：同时避免 overthinking、reward hacking，维持角色和人格时，线性叠加会怎样？TACT 处理两方向重叠，ATLAS 用联合核，但原始主张认为尚无系统组合律研究。
- 做法：测可加性、副作用耦合、正交化 vs 保留重叠、子空间乘法 vs 多向量加法。
- 产出：什么时候能组合，什么时候互相破坏。

### 8. 多 agent 中的 persona 异质性

- 问题：相同角色但不同人格能否改善协作？例如谨慎 reviewer 与激进 coder。原始主张认为 DRAS 只研究 role 越界，尚无人拆开 role 与 persona。
- 做法：固定 role，通过 steering 变化 persona，测协作质量、多样性、错误互相纠正；比较 prompt 异质性。
- 原始优势主张：steering 能精细控制强度，而 prompt 做不到。

### 9. 公平对比与鲁棒性

- 问题：相同算力、数据预算下 steering、prompt、LoRA 谁更好？steering 的优势是成本、可逆性、动态性还是其他？
- 另一部分：长历史、prompt injection、用户施压是否盖过 steering？
- 原始定位：审稿人关心的对比与鲁棒性问题。

### 10. 与显式记忆的接口

- 问题：动态 K 可理解为隐式控制状态；它与检索、摘要等显式 memory 是互补、冗余还是冲突？compaction 后 persona 状态如何保持？
- 候选做法：compaction 后用 steering 补回 persona。
- 提醒：与方向 4 相交；恢复投影未必恢复表达。

### 11. Reasoning / MoE 的特殊性

- 问题：steering 是否改变 MoE expert routing？thinking token 与 action token 干预有何差别？对推理长度、自我纠错有什么副作用？
- 原始定位：更像实证规律，适合作为其他方向的子实验，不太适合独立成文。

## 对 11 个方向的评估

| 方向 | 判断 | 需要明确的问题 |
| --- | --- | --- |
| 1 读出、动作、轨迹 | 值得做，也是共同评价骨架 | 三者不是严格递进的阶梯。probe 不成功不代表不能控制；动作改变也未必有益。研究哪些局部指标预测实际控制效果、何时失效。 |
| 2 行为型 persona | 有潜力，但不宜先建立完整新分类 | 从具体 agent 需求出发，区分稳定倾向与状态依赖策略。与 Big Five 的对应关系是结果，不是前提。 |
| 3 位置迁移 | 好的实验维度 | 以计划到行动的迁移、反馈后的有效性变化等问题组织矩阵，避免只做配置比较。 |
| 4 drift 机制 | 具体、适合解释性研究 | 先复现投影与输出脱节，检查测量位置、强度、阶段与指标，再检验路径解释。KV 等目前只是候选解释。 |
| 5 在线更新 | 值得探索，但需要需求依据 | 先判断有效方向是否随反馈或任务阶段变化；固定方向、只调强度可能已足够。 |
| 6 通用控制器 | 起点偏大 | 从具体失败中识别可复用部分，避免同时承担检测、校准、控制与多风险协调。 |
| 7 组合干扰 | 有直接先例，仍有 agentic 空间 | 将表示重叠、控制干扰和任务本身的权衡分开；不能以第一次研究组合定位。 |
| 8 多 agent 异质性 | agent 需求明确，值得考虑 | 区分角色分工、采样多样性、行为倾向变化；人格差异不必然形成能力互补。 |
| 9 对比与鲁棒性 | 通常是支撑实验，也可独立 | 当问题本身是部署成本、反馈干扰或可逆动态控制时可成为主线，而非只为回应审稿人。 |
| 10 显式记忆接口 | 贴近长期 agent 需求 | 保存信息与持续按照信息行动不同。明确维持的是目标、角色约束还是倾向，不假定 steering 保存任务事实。 |
| 11 架构与推理 | 不应一概降为子实验 | 换模型验证是控制；研究计算结构如何影响控制可以独立。关键在 reasoning 阶段、routing 与行为的联系。 |

### 方向 7 的直接先例

[ID7 · PERSONA](https://arxiv.org/html/2602.15669) 已研究向量加减、多 trait 干预、跨维度影响与组合可预测性。[Do Personality Traits Interfere?](https://arxiv.org/abs/2602.15847) 报告去掉几何重叠后跨 trait 行为影响仍存在，硬正交化还可能削弱控制。因此，基础组合问题已有直接研究，不应声称尚无人系统研究。

agentic 延伸仍有空间：对话 trait 表达与同时充分验证、避免重复、遵守角色、完成任务，是不同的评价终点。需要区分：

1. **表示重叠**：方向共享成分。
2. **控制干扰**：联合注入削弱某个方向的效果。
3. **任务权衡**：即使独立控制，更多验证也可能天然耗时。

cosine similarity 或正交化实验本身无法区分这三者。

### 不应沿用的过强表述

- “没人系统做过”“只有 ATLAS”应视为待检索主张；现阶段最多说已读集合中尚未看到。
- Prompt 也能通过措辞、例子和约束调整强度。steering 的精度、重复性和成本优势需要实证比较。
- 稳定性分析的价值取决于是否解释反馈导致的失效，而非只列系数与是否发散。
- 架构方向是否独立取决于问题与证据，不取决于它属于哪根实验轴。
- 新算子、完整机制和 benchmark 提升不是每项研究必须同时具备的要求。重要、可复现的现象与明确因果证据本身可以构成贡献。

## 重新组织的三条主线

### 主线一：Agent 在不同状态下需要怎样的行为倾向？

以方向 2 的需求为起点，借助方向 3、5 研究位置依赖和适应性，用方向 1 检验局部控制与实际 rollout 的关系。

核心关注：行为倾向是否随任务状态改变；从语言表达提取的控制能否影响动作；局部预选指标能否预测闭环收益。人格、人类 trait 和 agent 行为之间的对应关系不预先假定。

当前倾向：适合作为起点。可以从一个具体需求和有限实证问题开始，不必立即建立新分类、通用 controller 或多 agent 系统。这是研究组织上的判断，尚未选定具体任务与实验。

### 主线二：长程反馈中，如何保持应当保持的东西，同时进行必要适应？

连接方向 4、5、10。先定义什么需要稳定：目标、角色边界、行为倾向，还是回答表达；再区分合理策略调整与有害偏移。

核心关注：环境反馈、历史积累、压缩如何影响持续控制；显式信息记忆与隐式控制状态如何交互；投影恢复是否对应行为恢复。不能把目标偏离、角色越界、风格变化合成一个未经区分的 drift 分数。

当前倾向：与用户对 drift 的兴趣高度相关，但首先需要明确“保持什么”和它为何影响 agent。

### 主线三：多个行为要求如何共同影响单 agent 或团队表现？

连接方向 7、8，用方向 1 区分局部行为改善与整体系统结果。

核心关注：控制能否形成有用协同，何时产生干扰，何时只是任务本身存在取舍。单 agent 的多目标控制与团队中互补行为应分别评价，不能仅凭向量可加或人格不同推断系统收益。

## 共同评价原则与待定事项

- Agent 的行动会改变反馈，继而改变后续状态分布。离线 replay、局部动作干预、完整闭环 rollout 回答不同问题；replay 不足以替代闭环效果。
- 区分离线 trace 提取、在线调强度、在线更新方向／子空间。
- 表达分数、下一步动作、轨迹行为、任务成功、副作用与成本分别记录。不要把少行动、早放弃或少尝试误当成控制改善。
- 基本算子能用于 dense、reasoning、MoE，不等于这些设置对有效性没有影响。
- 先确定研究问题，再缩小对象、任务和评价终点；尚未选择最终方向，也未授权或安排新实验。

维护方式：后续讨论更新本文对应位置；正式文献结论继续维护在方向评估及单篇笔记，避免在这里复制不断变化的文献证据表。

## 从 agent 需求出发的痛点地图：博客与论文补充

本节为定向检索与初步综合，不是系统综述或每篇全文精读。博客核对正文，论文以摘要为主；MANDATE 另外查阅分类正文。表中“常见”指在这些来源中被讨论或测量，不代表已估计真实部署中的总体发生率。以下分类是阅读综合，不是任何单篇论文的原始 taxonomy；一条失败轨迹可涉及多类。

### 需求、可观察失败与常规处理

| Agent 需求／痛点 | 具体表现与重要区别 | 非 steering 处理与评价提示 | 来源 |
| --- | --- | --- | --- |
| 理解用户目标、澄清缺失条件 | 未确认关键条件就猜；把用户错误前提当事实；询问泛泛而无法推进 | 澄清策略、交互式规格、意图检查；同时测最终正确性与交互成本 | [AskBench](https://arxiv.org/abs/2602.11199)，多轮 QA，不是工具执行 |
| 用户偏好与个性化 | 识别不了隐含偏好；记住却未应用；旧偏好与新要求冲突 | 偏好记忆、检索、提醒、个性化训练；区分推断、保留、应用。偏好不等于 agent 人格 | [PrefEval](https://arxiv.org/abs/2502.09597)，长上下文／跨会话对话，不是环境 rollout |
| 复杂指令与约束遵循 | 忽略条件规则、工具限制或输出要求；多个约束难以同时满足 | 约束清单、结构化验证、指令训练；读得到规则与实际遵循分开 | [AgentIF](https://arxiv.org/abs/2505.16944)，真实应用指令来源，但不能据此当成长程执行实验 |
| 业务政策与交互可靠性 | 用户请求、业务规则和 API 状态需共同满足；同一任务重复运行成败不一 | 政策检查、状态验证、规则执行器；任务成功之外看重复试验一致性 | [τ-bench](https://arxiv.org/abs/2406.12045)，模拟用户＋API 交互，以最终数据库状态评估 |
| 授权边界与合适自主性 | 未授权行动、扩大范围；也可能反复索要已给出的许可或无法推进 | 权限、审批、可撤销动作、授权状态记录；少越界与少打断同时评价 | [MANDATE](https://arxiv.org/html/2610.34748) §3.3，用户报告分类，不是频率代表性抽样 |
| 不确定性、求助与升级 | 不知道自己缺信息；知道不确定仍猜；求助问题过宽；把本可完成的工作交回用户 | 选择性求助、校准、人机交接；缺信息、缺能力、缺权限不同 | [HiL-Bench](https://arxiv.org/abs/2604.09408)，本次摘要级核对 |
| 规划、分解与依赖管理 | 一次做太多、遗漏前置步骤、局部子任务偏离总目标 | 分解、进度与依赖记录、局部检查点；不能把所有规划失败都归因于 persona | [AgentBench](https://arxiv.org/abs/2308.03688)；[long-running harness 博客](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) |
| 工具选择、参数与真实状态理解 | 调错工具、参数错误、误把调用返回文字当实际成功；工具本身也可能故障 | 工具描述、schema、返回验证、重试与事务；定位模型／harness／环境责任 | [Model or Harness?](https://arxiv.org/abs/2607.28802)；[τ-bench](https://arxiv.org/abs/2406.12045) |
| 反馈采纳、纠错与恢复 | 无视失败继续同一策略；反复重试；从局部错误无法恢复；被错误反馈误导 | 状态检查、错误分类、回滚、重规划；反馈正确性也需检查 | [多 agent 工程博客](https://www.anthropic.com/research/multi-agent-research-system)；[Model or Harness?](https://arxiv.org/abs/2607.28802) |
| 长期记忆、更新与跨会话连续性 | 忘事实、取错时间版本、沿用过期状态；恢复会话时不清楚已完成什么 | 检索、时间标记、知识更新、工作产物交接；记忆内容正确不等于行动采纳 | [LongMemEval](https://arxiv.org/abs/2410.10813)，记忆 QA；[long-running harness 博客](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)，真实工程经验 |
| 目标、角色与表达的长期稳定 | 逐步偏离目标、越过角色边界、回答方式变化；合理策略更新不应算失败 | 约束重注入、交接、监测、上下文管理；分别定义目标／角色／表达的偏移 | 已有 [ContextEcho](https://arxiv.org/abs/2605.24279)、[DRAS](https://arxiv.org/abs/2610.15907) 阅读，见方向评估；不混成统一 drift |
| 验证、完成判断与诚实汇报 | 未测试就宣布完成；说执行了未执行的步骤；错述环境或引用证据 | 外部测试、完成标准、证据绑定汇报；未验证、误判、虚假陈述不自动等于有意欺骗 | [long-running harness 博客](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)；[MANDATE](https://arxiv.org/html/2610.34748) |
| 停止决策与资源管理 | 过早结束、无效循环、过度搜索／思考／调用；未预留完成所需预算 | 停止规则、预算、去重、分阶段验证；效率应与任务进展联合测量 | [MANDATE](https://arxiv.org/html/2610.34748)；已有 TACT 阅读 |
| 外部输入的信任与安全 | 文档／工具返回劫持目标、泄露信息或诱导未授权动作 | 信任边界、隔离、指令层级、权限与输出检查；攻击成功率与正常任务效用分开 | [AgentDojo](https://arxiv.org/abs/2406.13352)，不可信工具数据下的执行环境 |
| 多 agent 协作与责任分配 | 重复劳动、缺失交接、互相误解、没有人验证或终止 | 明确责任、通信与共享状态协议、协调与验证；区分团队结构失败和单模型失败 | [MAST](https://arxiv.org/abs/2503.13657)；[多 agent 工程博客](https://www.anthropic.com/research/multi-agent-research-system) |
| 真实目标、奖励与训练泛化 | 满足评分而不完成目标；训练强化捷径；窄任务学到的行为向其他场景泛化 | 修复环境／奖励、轨迹审计、训练数据与安全训练；部署作弊率与训练后的泛化分开 | [Natural Emergent Misalignment](https://arxiv.org/abs/2511.18397)，生产 RL 环境研究 |
| 评估、监控与归因 | 最终失败标签掩盖真正出错组件；输出流畅或 benchmark 分数不能说明过程可靠 | 分步 trace、真实环境状态、成本、失败归因；它是横切的研究／工程痛点 | [Model or Harness?](https://arxiv.org/abs/2607.28802)，摘要级核对 |

另保留原表的“RL 探索塌缩”作为训练侧痛点，但本次没有专门核对其 agent RL 来源，不据此声称它是本次来源中得到验证的常见现象。它与部署时探索不足相关但不等价，后续训练侧综述需单独补证。

### 先诊断来源，再判断倾向／能力

“模型会但没做”是有用的切入点，但不适合作为整张地图的第一道二分筛选。建议先检查：

1. **信息与状态**：约束、偏好和工具反馈是否真的提供给当前模型？是否被截断、压缩或检索遗漏？
2. **能力与可达性**：所需知识、规划、工具与权限是否足够？在同状态给予合理支持后是否能完成？
3. **行为选择**：条件具备时，是否仍反复选择不验证、猜测、越界或走捷径？
4. **系统与激励**：harness、环境、错误反馈或评分是否诱导／制造失败？

这个顺序是阅读综合提出的诊断方式，不是经过验证的因果分类器。来源 [Model or Harness?](https://arxiv.org/abs/2607.28802) 明确支持将同一可见失败定位到不同组件；“忽略指令”可能是模型未遵循，也可能是约束早已丢失。一次成功或某个 prompt 下成功也不足以证明模型在原条件下稳定具备能力。

Activation steering 会改变计算过程和可观察性能，不能以“只改变倾向、不改变能力”作为定理。更准确的工作假设是：它可能调节已有表征和策略的使用，但是否改善推理、引入能力副作用或只能改变表达，需按任务检验；没有依据假定一个方向能凭空补足缺失知识或外部权限。

### 对 Claude 其余前提的核对

- **“不占上下文”**：直接注入通常不需要额外控制文本，但提取、监测和选强度可能有额外推理成本。**“不随上下文长度稀释”没有保证**：后续计算、上下文、位置与环境反馈仍会影响最终行为。
- **Read 比文本早**：某些位置可以在行为发生前预测；不代表所有 probe 都提前，也不代表更难被规避。需另测校准、干预后分布变化和对抗适应。
- **ContextEcho 的负结果**：支持测试配置下轴投影恢复不足以恢复目标表达；不能由此确定 Axis 不在因果通路，或把 KV／多路径等假设当结论。
- **Preventative steering 已核对**：原 Persona Vectors 在有害特征诱导的微调中，训练时沿不良特征方向添加激活，使拟合训练数据无需同样程度地改变参数；推理时移除外加 steering。它不是简单在训练 rollout 中压低坏行为，更不是已证明可直接迁移到 agent RL 的方案。来源：[原研究博客](https://www.anthropic.com/research/persona-vectors)。
- **Reward hacking 与 RL**：真实生产 RL 环境中已有 reward hacking 与更广行为泛化的研究，支持其重要性；并不意味着所有作弊都会泛化、或一个 probe／steering 就能阻断训练中的形成机制。来源：[原论文](https://arxiv.org/abs/2511.18397)。
- **Persona 抽象**：具体行为可能共享表征，但 emergent misalignment 本身不证明存在统一、稳定、便宜且可跨任务控制的 persona 变量。这仍是经验问题。

### 对三条主线的影响

原三条主线保留为候选组织方式，不把它们当作完整 agent 痛点 taxonomy。新增偏好、指令遵循、授权／求助、记忆更新和诚实汇报后，应先保留完整需求空间，再筛选哪些有值得研究的表示或控制问题。无需立即将每一行对应到 steering，也不因为暂时不能由 steering 解决就删除。
