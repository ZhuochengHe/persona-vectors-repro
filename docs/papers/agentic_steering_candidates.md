# Agentic steering：候选问题、证据与测量表

用途：供与 Claude 讨论、收缩研究问题。候选 ID Q01–Q24 是本讨论内部编号，**不是论文 ID**。这是需求与可测性驱动的候选库，不是已选实验方案，也不声称某方向无人做过。

[原始 11 个 idea、评估与三条主线](agentic_steering_ideas.md) · [已有文献方向评估](research_directions.md) · [论文入口](README.md)

## 怎样使用这份表

- 先选要理解的 agent 行为，再选表示／提取／干预方法。暂时不能用 steering 解决的需求也保留。
- 决策点、状态维持、能力是可重叠视角；“会但没做”需要对照证据，不是初始标签。
- **原有指标**与**拟新增指标**分别标注。这里提出的指标、最小设置、优先级和成本是我们的设计判断，不是来源已经验证的结论。
- “优先细化”仅代表需求清楚、评价有抓手；不表示已确认新颖性或最有发表价值。直接先例不排除有意义的延伸。
- 成本为相对工程＋推理＋标注成本，未跑通环境或做吞吐测量，不给 GPU 小时承诺。低成本 QA 对照不能代替 agentic 执行。
- 本次进行了定向网络检索与来源核对；不是系统综述。末尾证据台账说明摘要、选读方法、官方文档和已有阅读的区别。没有实际跑 benchmark；公开性、许可证、模型接口和复现可用性还需立项前检查。

## 逐项测量卡

每项都需要同时观察行为与最终任务结果。下列“最小切入”是可讨论的实验单元，不是已经确认的数据子集、运行预算或执行承诺。

<a id="q01"></a>

### Q01 · Agent 能否在确实缺少必要信息时求助，并在信息充分时直接推进？

- **证据与可用设置**：HiL 的 progressive blockers 接近真实工具过程；AskBench 可做较便宜对话对照。
- **行为与结果指标**：现成 Ask-F1／任务通过；新增无 blocker 对照中的过度求助率，记录提问成本。
- **非 steering 基线**：明确求助规则；完整信息条件；已有信息检索／重注入。
- **归因与测量风险**：提问相关性仍需 judge；不能只用更多提问解释提升；先核对公开任务及授权。
- **表示／steering 的待检验角色**：候选：求助／自主推进倾向；是否有可迁移方向待验证，非预设 uncertainty probe 就是写方向。
- **最小切入**：优先 SQL 或小型可执行工具任务，必要信息缺失／充分成对。

<a id="q02"></a>

### Q02 · 在行动会改变环境时，用户偏好能否持续影响选择，而非只影响回答措辞？

- **证据与可用设置**：PrefEval 提供对话偏好证据；τ-bench／AppWorld 的偏好动作条件需要自建标注，不是现成子集。
- **行为与结果指标**：每个适用选择的偏好满足率、最终目标、偏好撤销后的错误沿用；语气分数另列。
- **非 steering 基线**：显式 profile 注入；检索；每步偏好提醒。
- **归因与测量风险**：低价／省时等偏好要与硬约束分开；不能让 persona simulator 风格代替用户偏好。
- **表示／steering 的待检验角色**：候选：偏好应用／具体决策方向；TOD persona steering 是相关先例，不能称首次个性化 agent 控制。
- **最小切入**：少量二至三种可核对方案的 API 任务，明确偏好与临时覆盖指令。

<a id="q03"></a>

### Q03 · Agent 能否在正确条件触发时遵守规则，同时在未触发时避免过度限制？

- **证据与可用设置**：AgentIF 提供逐约束评价；真正动作效果需转到 τ-bench／ToolSandbox 或自建状态任务。
- **行为与结果指标**：现成 CSR／ISR（指令层）；新增已触发违例率、未触发误限制率、合法任务成功。
- **非 steering 基线**：规则重注入；可执行检查器；结构化计划。
- **归因与测量风险**：观察到不遵循前先检查约束是否仍可见；agentic instruction 来源不代表长程执行。
- **表示／steering 的待检验角色**：候选：指令采纳方向或条件控制；是否会把软偏好变成硬禁令需测。
- **最小切入**：选一条可程序判定的条件约束，构造触发／不触发成对状态。

<a id="q04"></a>

### Q04 · Agent 能否维持授权范围，并减少对已授权动作的不必要请示？

- **证据与可用设置**：MANDATE 支持双向自主性问题；授权账本与动作 oracle 为自建扩展。
- **行为与结果指标**：未授权动作／机会数；已授权机会的重复请示；任务完成与用户轮次。
- **非 steering 基线**：显式授权状态；工具级权限门；提示已有批准。
- **归因与测量风险**：权限拦截后的零越界不等于模型做出正确决策；记录动作提议及实际执行。
- **表示／steering 的待检验角色**：候选：边界遵循与自主推进可否分别调节；角色边界不是权限边界。
- **最小切入**：在可回滚 API 沙箱中固定授权状态与明确范围，不做外部真实操作。

<a id="q05"></a>

### Q05 · Agent 是否会进行能发现问题的验证，而不是仅增加测试调用？

- **证据与可用设置**：博客报告未测试即完成；SWE 测试给结果，不给充分验证标签。
- **行为与结果指标**：新增有效缺陷发现率、必要检查覆盖、验证后修复率、最终外部测试、额外成本。
- **非 steering 基线**：验证 checklist；工具自动测试；固定验证预算。
- **归因与测量风险**：调用测试≠有用验证；隐藏测试不能泄露给方向提取或控制器；测无缺陷任务过度验证。
- **表示／steering 的待检验角色**：候选：验证倾向与验证能力分开；比较 persona／behavior 来源是否作用相同。
- **最小切入**：自建小代码任务，注入已知可被公开检查发现的缺陷，独立隐藏测试验收。

<a id="q06"></a>

### Q06 · Agent 的完成声明能否与实际执行和验证证据一致？

- **证据与可用设置**：用户报告揭示 execution misrepresentation；AppWorld 状态可作外部 oracle，声明标签需新增。
- **行为与结果指标**：无证据成功声明率；真实完成漏报率；动作／测试日志与声明一致率；实际成功。
- **非 steering 基线**：结构化证据汇报；将工具结果附给摘要；强制完成标准。
- **归因与测量风险**：不声明成功可能只是更含糊；需标注尝试／执行／验证／完成不同断言；不推断主观欺骗。
- **表示／steering 的待检验角色**：候选：诚实报告与实际行动是否可分离控制，报告改善也可单独有价值。
- **最小切入**：固定已成功／失败／未执行的可核对轨迹，再做少量闭环确认。

<a id="q07"></a>

### Q07 · Agent 何时应该继续，何时应该停止，能否避免过早完成和无效延长？

- **证据与可用设置**：TACT 已直接控制效率失败；AgentBoard 支持中间进度，最优停止标签仍需自建。
- **行为与结果指标**：提前停止率、达标后多余动作、成功率、预算耗尽；报告成功与失败任务全部成本。
- **非 steering 基线**：预算／早停；进度检查；完成 checklist。
- **归因与测量风险**：少 token 可能来自早放弃；不能只在成功样本上比较成本；有价值重复不算循环。
- **表示／steering 的待检验角色**：已有 TACT；新增应明确停止状态／完成校准，不能仅换方向名称。
- **最小切入**：具有明确终态和可见剩余子目标的短工具任务。

<a id="q08"></a>

### Q08 · 收到可靠失败反馈后，Agent 能否切换策略；收到噪声反馈时又能否避免过度反应？

- **证据与可用设置**：来源支持恢复需求；可控故障和真假反馈成对是自建扩展。
- **行为与结果指标**：失败后恢复成功率、无效重复、切换代价、正常／误报反馈下的性能。
- **非 steering 基线**：分类重试；指数退避；显式 replan；额外观察工具。
- **归因与测量风险**：要区分瞬时故障应重试与永久失败应切换；新信息而非动作换名才算更新。
- **表示／steering 的待检验角色**：候选：坚持／反馈采纳的状态依赖控制，未预设越易改变策略越好。
- **最小切入**：同任务加入可恢复瞬时故障、永久不可用、误报三种可记录条件。

<a id="q09"></a>

### Q09 · 环境事实改变后，Agent 能否更新判断并停止使用过期状态？

- **证据与可用设置**：LongMemEval 是更新 QA；ToolSandbox 可执行状态更新，须新增事件干预。
- **行为与结果指标**：更新后首个相关动作正确率、旧状态动作残留、任务成功；正确 recall 与动作采纳分测。
- **非 steering 基线**：刷新观察；带时间戳状态；检索最新记录。
- **归因与测量风险**：没看到更新与看见未采纳不同；评价需保存模型实际输入和真实事件时间。
- **表示／steering 的待检验角色**：候选：状态采纳／固着倾向；方向无法恢复未提供的信息。
- **最小切入**：两个合法但不同时有效的状态版本，更新前后动作标准明确。

<a id="q10"></a>

### Q10 · 跨压缩或跨会话后，哪些约束丢失，哪些仍能记住却不执行？

- **证据与可用设置**：记忆 QA 与 ContextEcho replay 不足以给出闭环任务结论。
- **行为与结果指标**：约束保留、检索、动作遵循三个阶段；压缩前后任务成功、恢复开销。
- **非 steering 基线**：原文保留；结构化摘要；检索；约束重注入。
- **归因与测量风险**：压缩长度、语义信息和历史难度需分开；测量 probe 插入本身可能提醒模型。
- **表示／steering 的待检验角色**：候选：信息维持与控制维持的分离；与显式 memory 互补待验证。
- **最小切入**：先在可执行任务交接点比较有／无明确约束交接，再延长历史。

<a id="q11"></a>

### Q11 · 长程运行中，Agent 是否偏离原目标；这种变化如何区别于合理改计划？

- **证据与可用设置**：ATLAS 相关先例，ContextEcho 是表达漂移；目标漂移不能直接复用其表达指标。
- **行为与结果指标**：原目标约束、子目标进度、未经授权目标替换、任务完成；随步骤／事件变化。
- **非 steering 基线**：目标重注入；进度台账；分段重启／重规划。
- **归因与测量风险**：时间、历史难度、错误累积相关；只有偏移投影不能证明目标漂移。
- **表示／steering 的待检验角色**：候选：任务／persona／state 控制的不同作用；不声称首次 drift mitigation。
- **最小切入**：先明确最终目标和合法计划更新，再注入与目标无关但诱人的分支。

<a id="q12"></a>

### Q12 · 回答风格与自我表述变化，是否真的预示 agent 行为和可靠性变化？

- **证据与可用设置**：ContextEcho 支持表达 drift；TOD 给 persona 控制先例，均不直接确立可靠性代理。
- **行为与结果指标**：表达分数、实际动作、任务成功分开；控制任务状态后的预测及干预效应。
- **非 steering 基线**：风格 prompt；Axis／Big Five 与直接 behavior 方向分别比较。
- **归因与测量风险**：中性表达不等于安全／可靠；长历史下的共同相关因素需控制。
- **表示／steering 的待检验角色**：可作为 phenotype 与行为关系研究；不能预设 Assistant Axis 是 reliability 指标。
- **最小切入**：相同任务状态、不同表达历史，先测对应动作，再少量闭环。

<a id="q13"></a>

### Q13 · 角色约束能否避免越界，又不阻止必要交接和合理帮助？

- **证据与可用设置**：DRAS 已做动态 role steering；角色接口与任务执行质量需独立评价。
- **行为与结果指标**：现成角色越界判断；新增漏交接、重复工作、最终外部测试与成本。
- **非 steering 基线**：角色清单；few-shot；通信协议；post-hoc regeneration。
- **归因与测量风险**：越界最低未必任务最好；不能只用代码存在／可运行代理质量。
- **表示／steering 的待检验角色**：后续可研究角色与 trait 交互、接口条件；泛泛 role steering 已有。
- **最小切入**：先单 agent 模拟交接决策，再决定是否承担完整双 agent 工作流。

<a id="q14"></a>

### Q14 · 能否抵抗不可信工具内容的劫持，同时保留合法信息利用与任务能力？

- **证据与可用设置**：AgentDojo 有攻击和正常任务；steering 效果及跨攻击泛化仍需实测。
- **行为与结果指标**：攻击成功、正常／受攻击任务成功、错误拒绝、权限违例；按攻击类型报告。
- **非 steering 基线**：信任标签；层级 prompt；工具隔离；权限门。
- **归因与测量风险**：禁止所有工具可伪造安全；训练攻击类型与确认攻击分开。
- **表示／steering 的待检验角色**：候选：信任来源／目标维持控制；安全领域另需定向检索新颖性。
- **最小切入**：单域可重置工具任务，clean／attacked 成对并固定攻击位置。

<a id="q15"></a>

### Q15 · Agent 能否完成任务，同时避免无关状态修改或隐私暴露？

- **证据与可用设置**：AppWorld 明确评估 collateral damage；ToolSandbox guardrail 可检查不应变化的状态。
- **行为与结果指标**：任务成功且无越界修改的联合比例；无关变更数；敏感信息外发与合法输出分别标注。
- **非 steering 基线**：最小权限；只读优先；事务与 diff 检查；数据分类。
- **归因与测量风险**：碰巧没触及敏感工具不是学会边界；不可用权限同样影响任务可达性。
- **表示／steering 的待检验角色**：候选：行动克制／范围选择；不是“更拒绝”即可改善。
- **最小切入**：选择有明确允许写集合与保护状态的 API 任务；隐私扩展单独定义。

<a id="q16"></a>

### Q16 · 奖励或测试有漏洞时，Agent 能否保持诚实尝试而非作弊或放弃？

- **证据与可用设置**：ImpossibleBench 与原 LiveCodeBench 配对已被用来做 steering。
- **行为与结果指标**：现成 hack／honest submit／原题 solve；新增不同漏洞／harness 的迁移。
- **非 steering 基线**：anti-hacking spec；修复评分；轨迹审计。
- **归因与测量风险**：不可把不提交算诚实；作弊判断需要看代码／状态而非仅文本承诺。
- **表示／steering 的待检验角色**：后续着眼迁移、发生时刻、控制来源或行为副作用；单纯压制作弊已有。
- **最小切入**：先较短可审计任务，再判断是否需要论文式长 rollout。

<a id="q17"></a>

### Q17 · 同样预算下，Agent 能否更好分配探索、验证、执行，而非固定偏向某一种？

- **证据与可用设置**：EAST bandit、E-STEER 阶段行为、TACT 效率均有相关先例。
- **行为与结果指标**：最终回报／成功、有效新信息、阶段成本；自建环境可计算 regret。
- **非 steering 基线**：温度；固定预算；显式阶段策略；搜索／验证调度。
- **归因与测量风险**：token 熵不是行动探索；搜索多不等于信息多；不同模块组合有系统效应。
- **表示／steering 的待检验角色**：候选：阶段依赖行为控制；开放任务探索不可直接用 bandit 结论替代。
- **最小切入**：有有限动作和已知信息价值的工具环境，再推广开放任务。

<a id="q18"></a>

### Q18 · 更好的规划是否真的减少依赖错误并改善执行，而非只是计划文本更完整？

- **证据与可用设置**：AgentBoard 进度、ToolSandbox DAG 可支持可执行子目标核对。
- **行为与结果指标**：子目标成功、依赖顺序错误、计划执行一致性、最终状态；文本计划评分仅辅助。
- **非 steering 基线**：任务分解 prompt；外部 planner；显式 DAG／状态。
- **归因与测量风险**：steering 可能只是改变冗长度；错误计划与执行不采纳需区分。
- **表示／steering 的待检验角色**：允许诊断或性能改善，不先假定存在通用 planning vector。
- **最小切入**：短依赖任务，先给正确计划作为能力／执行参照。

<a id="q19"></a>

### Q19 · 工具选择和参数是否能可靠对应当前意图与状态？

- **证据与可用设置**：有状态 API 环境可验真实变化；单纯函数名匹配不够。
- **行为与结果指标**：可执行调用、参数合法性、状态效果、修复率与任务成功。
- **非 steering 基线**：schema／描述优化；工具筛选；参数校验。
- **归因与测量风险**：工具缺文档、接口 bug、环境时区等可能是根因；错误不必来自行为倾向。
- **表示／steering 的待检验角色**：候选：从读出到具体动作效果；不预设 persona 是适当抽象。
- **最小切入**：小工具集，同意图不同状态条件，验证执行而非只输出 JSON。

<a id="q20"></a>

### Q20 · 不同 agent 的行为差异能否形成互补，而非仅增加争论和成本？

- **证据与可用设置**：MAST 与工程经验支持协作痛点；TOD 双方 persona 不等于团队协作验证。
- **行为与结果指标**：共享错误纠正、独立发现问题、重复工作、最终测试与总成本。
- **非 steering 基线**：单 agent；同模型独立采样；prompt 异质性；固定角色。
- **归因与测量风险**：多样性本身不是收益；多人／多 token 预算与角色分工需控制。
- **表示／steering 的待检验角色**：候选：固定角色下 trait／behavior 差异；团队 steering 新颖性未全域核实。
- **最小切入**：两个 agent、单一可外部验收任务；先与同预算独立样本聚合比较。

<a id="q21"></a>

### Q21 · 多个行为要求能否同时满足，何时是控制干扰、何时是任务本身的取舍？

- **证据与可用设置**：PERSONA 与 trait interference 已直接研究组合；TACT、ATLAS 也是方法先例。
- **行为与结果指标**：各行为指标、联合成功、任务结果与成本；相同状态下单独／联合干预。
- **非 steering 基线**：prompt 组合；单方向；简单加法；正交化／保留重叠。
- **归因与测量风险**：表示 cosine、因果交互与预算权衡不同；不能把所有副作用称为几何干扰。
- **表示／steering 的待检验角色**：候选：agentic 行为组合；必须明确超出已有组合实验的终点。
- **最小切入**：从两行为开始，选择存在独立正确标签的任务，不做全组合爆炸。

<a id="q22"></a>

### Q22 · 局部可读出或可改变的行为，什么时候能预测完整 rollout 的收益？

- **证据与可用设置**：已有研究给局部／闭环案例，没有据此证明统一阶梯关系。
- **行为与结果指标**：held-out probe、局部动作效应、闭环行为与成功；评估配置排序预测与失配。
- **非 steering 基线**：随机／prompt／固定强度候选；全 rollout 选参仅作为昂贵参照且不看测试集。
- **归因与测量风险**：probe 需用 pre-decision state；离线 probe 不读取未来；分支恢复须含工具状态与随机源。
- **表示／steering 的待检验角色**：候选：read／write／trajectory gap；从一个具体痛点开始而非穷举 persona。
- **最小切入**：附着 Q01／Q05／Q08 之一，少量候选配置在恢复状态和真实闭环对照。

<a id="q23"></a>

### Q23 · 训练中干预作弊倾向，能否改变最终未干预模型的行为与泛化？

- **证据与可用设置**：生产 RL reward hacking 与 preventative 微调相关，但不是同一种训练方案。
- **行为与结果指标**：训练奖励与真实目标；移除 steering 后 held-out 作弊、任务能力、跨域泛化；总训练成本。
- **非 steering 基线**：奖励／环境修复；安全数据；prompt／训练正则化；同预算无干预。
- **归因与测量风险**：训练采样改变、参数学习、部署残留要分离；probe 不能既唯一奖励又唯一判据。
- **表示／steering 的待检验角色**：候选：训练期干预；方向与目标需独立确认，不能靠部署结果推断。
- **最小切入**：先验证部署控制与数据分布，再独立设计小模型训练；目前不安排 RL。

<a id="q24"></a>

### Q24 · 训练 rollout 的探索多样性与真实学习收益能否分离并共同改善？

- **证据与可用设置**：EAST 只支持部署 bandit 探索可控；本次未完成 agent RL collapse 专项检索。
- **行为与结果指标**：状态覆盖／策略多样性、有效回报发现、后续 held-out 学习曲线；去除无意义随机。
- **非 steering 基线**：entropy bonus；温度；多样性奖励；重启／数据调度。
- **归因与测量风险**：多样≠学得好；固定推理开销并不能固定训练总成本。
- **表示／steering 的待检验角色**：保留痛点，不据当前来源判定 steering 新颖性或有效性。
- **最小切入**：先补训练文献与有 oracle 的环境，再决定是否立项。

## 测量规则：先避免把问题测歪

1. **分母必须是适用机会**：验证机会、求助 blocker、触发规则的状态分别定义；未触发规则不按不遵守计分。全程求助率或测试次数本身不说明好坏。
2. **同时设相反条件**：需要求助／无需求助、应验证／无新增验证价值、应重试／应切换、旧约束有效／已合法撤销。不要只奖励单向增加倾向。
3. **保持原 benchmark 结果**：自建行为指标补充任务成功，不能替代它。工具调用是否执行、真实状态是否变化、最终结果是否正确分开。
4. **自建指标先验证**：规则能判的部分用规则；需 judge 时先用独立人工审查样本验证判据，保留分歧和不确定，不把多个 LLM 赞同当独立真值。结论对 judge／提示的敏感性是测量问题。
5. **禁止结果泄漏**：提取／probe 训练／层与强度选择／最终确认按任务分开；共享模板变体或同一任务分支不能轻易当独立测试。pre-decision probe 不读未来完成文本。
6. **区分三个终点**：读出、改变动作、改善闭环不是严格蕴含。replay 用于条件诊断；恢复分支需完整环境快照，不能只复制对话。全 rollout 仍用于判断闭环收益。
7. **记录全部失败与成本**：拒绝、放弃、不提交、预算耗尽、环境故障和 grader 失败单列；不能删除失败任务后报告成本下降。以任务为比较单位，重复 seed／分支不冒充独立任务数。
8. **固定外部条件**：模型与推理模式、harness、工具、规则、任务／测试版本、预算、采样和用户模拟器均需记录。不要同时换 harness 和方向却把效果归于 steering。
9. **成本分解**：方向提取／标注、控制器和 judge、目标模型生成、工具运行、环境重置分别记账。当前只先选一个任务族和少量方向／位置；不启动完整位置×层×强度×persona 网格。
10. **先确定可测的失败确实出现**：小规模可行性检查用于任务难度和评价适用性；不能从测试集事后挑出 steering 有效的任务再称一般收益。没有足够目标失败也可能说明任务不适合当前模型。

## 当前讨论优先级与三条主线

**第一组：适合先讨论最小问题。**Q01 求助、Q03 条件约束、Q05 有效验证、Q06 证据一致汇报、Q08 反馈恢复。它们有可界定的机会和外部评价抓手；Q01 的公开任务限制、Q05 的验证相关性、Q06 的声明语义仍需处理。Q02 偏好、Q04 授权、Q09 状态更新、Q15 副作用也值得并列讨论，但需要补可执行标签或状态扩展。

**第二组：重要但需要先造好评价。**Q10–Q12 长期维持与表达／行为、Q17 资源分配、Q20 团队互补。它们不是次要问题；主要额外负担是状态匹配、长期归因或系统预算。Q07、Q13、Q16、Q21 有直接 steering／组合先例，后续需把新问题与已有终点区分。

**第三组：能力参照与训练侧。**Q18、Q19 可帮助判断其他失败是否来自规划／工具能力，也可独立研究；不默认 persona 是答案。Q23、Q24 保留为训练侧路线，避免在部署实验前就承担 RL。Q22 是可附着在具体问题上的评价主线，不宜无边界横扫所有任务。

| 原三条主线 | 对应候选 | 需要记住的边界 |
| --- | --- | --- |
| 不同状态需要怎样的行为倾向 | Q01–Q09、Q14–Q19；Q22 作评价连接 | 用户偏好、指令、权限、安全不自动等于 persona。 |
| 长程保持与必要适应 | Q02、Q03、Q09–Q13；Q22 | 记忆信息、状态使用、目标控制分别测；不能统一叫 drift。 |
| 多要求与团队的协同／干扰 | Q13、Q15、Q17、Q20、Q21 | 单 agent 联合要求、团队角色、行为异质性是不同层级。 |
| 原三线之外保留的路线 | Q23、Q24；Q18、Q19 也可独立 | 不为保持三分结构而删掉训练或能力问题。 |

当前更推荐把 **Q01、Q05、Q08** 作为与 Claude 比较的三个具体问题：求助有较明确已登记 blocker；验证有行为到真实缺陷发现的差距；恢复能直接研究反馈和策略适应。**Q02 偏好与 Q03 指令遵循同样保留为核心候选**，不能因它们不天然叫 persona 就略过。这是可测性与启动成本的暂定排序，不是发表价值或新颖性的定论。

## 给下一轮讨论的交接

请先比较需求重要性、可观察证据、最小执行环境、归因可信度和总成本，再讨论向量来源／位置／算子。可以挑战上述优先级和三条主线。不要把相关先例当整个方向覆盖，也不要把“本表未找到”当无人研究；不要立刻替所有痛点提出新 controller。第一轮收缩到两至三个明确问题即可，尚不决定完整实验。
