# E08: Measure persona drift after ordinary SFT

## Question and scope

Which kinds of fine-tuning data change the model's expression of evil, sycophancy, or hallucination? E08 reproduces the paper's §4.1 dataset comparison using the fixed 5 × 3 matrix in `docs/plans/selected_experiments_adaptation.md`: `evil`, `sycophancy`, `hallucination`, `insecure_code`, and `mistake_opinions`, each in Normal, I, and II versions. This is a behavior study of the three named traits; it does not add other trait outcomes.

## Data and model

- Use the author's JSONL message records from `dataset/{evil,sycophancy,hallucination,insecure_code,mistake_opinions}/{normal,misaligned_1,misaligned_2}.jsonl` in the fixed upstream archive. The filename-to-version mapping is Normal → `normal`, I → `misaligned_1`, II → `misaligned_2`.
- Freeze stable question-group manifests before training: up to 1,000 groups for train and 100 disjoint groups for development per category. Align Normal/I/II by normalized user-question content and stable hash, not row index. For `mistake_opinions`, choose one response per question before splitting. If fewer than 1,100 common groups exist, use all available common groups and record counts; never repeat rows to fill a subset.
- First run the exact pipeline with 200 training groups per version as a pilot. Once data and token boundaries are audited, train on the frozen 1,000-group subset. Pilot adapters are not part of the 15 formal results.
- Use `Qwen/Qwen3.5-4B`, non-thinking text-only mode, with the same resolved model revision and tokenizer across all runs. Use MMLU only for capability evaluation, never as SFT data.
- Train one epoch with rs-LoRA rank 32, alpha 64, dropout 0, learning rate `1e-5`, per-device batch size 2, gradient accumulation 8, maximum sequence length 2048, seed 0. Match train/dev manifests and every setting in E11.
- Use the upstream optimizer settings explicitly: `adamw_8bit`, weight decay `0.01`, linear learning-rate decay, five warmup steps, and logging every optimizer step. Use BF16, gradient checkpointing, response-only loss, and no packing or 4-bit base-model quantization. Rank/alpha/LR/epochs/batch/accumulation are specified in Appendix D.3; optimizer/scheduler/length settings come from `upstream/configs/train_instruct_7b.json`. LoRA targets are adapted to Qwen3.5 text-block linear projections, excluding vision and the LM head.
- Training preflight: run Evil-II with 200 training groups and the same 100 development groups reserved after the first 1,000 shuffled groups, one epoch (13 optimizer steps). Validate finite loss/gradient logs, nonzero LoRA parameter change, peak GPU memory, adapter save/reload, and a short generation. This pilot is excluded from formal E08 comparisons; it does not establish worst-case 2,048-token Code-batch memory or behavioral drift.

## Training and measurements

Run `src/persona_repro/training.py::train_adapter` once for each of the 15 data/version pairs, without a steering vector. Train only discovered linear projections within the 32 text decoder blocks; record the exact target names because Qwen3.5 uses hybrid attention. All other parameters, including any visual modules and `lm_head`, remain frozen. Compute loss only on assistant response tokens using the shared non-thinking chat encoder; retain message terminators that belong to assistant turns and do not append a second EOS token.

After each adapter is saved, evaluate its responses on the same frozen 10-question final set for each of `evil`, `sycophantic`, and `hallucinating`, with 10 paired rollouts per question and fixed generation settings. Score with `gpt-5.6-luna` and the upstream trait rubrics plus coherence rubric, without calibration. Evaluate all adapters and the base checkpoint on the same fixed stratified 1,000-question MMLU test subset. The development questions may be used to check the pipeline and choose later E10/E11 settings; they are not the reported test set.

Report all three trait means and paired changes from the base model for every adapter, coherence, MMLU accuracy, data group counts, training loss, truncation/invalid example counts, and exact adapter metadata. Cluster uncertainty by evaluation question. Keep outcomes for every matrix cell, including cells with no drift; E10's eligible checkpoints are selected from development results before final scores are inspected.

## Expected outputs

Store immutable subset manifests and one adapter plus metadata per cell under the configured run root, organized as `E08/{category}/{normal|I|II}/seed0/`. Save task, answer, judge, coherence, and MMLU records separately. The adapters are shared baselines for E09, E10, E11, and E19. There are no E08 results until these training and evaluation runs have been executed.
