# E09: Relate finetuning activation shifts to behavior changes

## Question and source

For the 15 ordinary SFT checkpoints from E08, do changes in the last-prompt-token projection along an E01 persona direction track changes in that trait's judged expression? This follows the finetuning-shift analysis in paper §4.2 and Appendix E. The scope is Qwen3.5-4B and the three fixed traits: `evil`, `sycophantic`, and `hallucinating`.

## Inputs and fixed defaults

- Use the same base model, E01 unit vectors, selected E02 layer, evaluation question IDs, rendered prompts, and generation/scoring settings as E08. Do not derive or refit directions from an E08 checkpoint.
- Include all five training categories (`evil`, `sycophancy`, `hallucination`, `insecure_code`, `mistake_opinions`) and each `normal`, `misaligned_1`, and `misaligned_2` version. Each checkpoint is identified by a stable `checkpoint_id` that maps to exactly one category/version/seed.
- Evaluate base and finetuned models on the same prompt IDs and paired rollout seeds. Judge with `gpt-5.6-luna` using the fixed trait rubrics; no separate calibration stage. Keep refusals and invalid scores explicit and fail the aggregate if required pairs are missing.
- Capture the final non-padding prompt token at the selected block output before final normalization. Projection uses the frozen unit E01 direction. Use identical prompt token IDs for base and finetuned forwards.

## Procedure

1. For each trait/checkpoint/prompt, save the base and finetuned last-prompt projection. For each paired response, save base and finetuned trait scores keyed by the same `trait`, `checkpoint_id`, and `prompt_id`.
2. Join projection and score tables on the exact `(trait, checkpoint_id, prompt_id)` key. Reject duplicate keys, missing keys, extra keys, non-finite values, or mismatched model/vector/layer metadata. Do not silently use a partial inner join.
3. Compute per-prompt activation shift as `finetuned_projection - base_projection` and behavior change as `finetuned_score - base_score`.
4. Average each quantity over prompts within trait/checkpoint. Report those paired checkpoint means, the number of prompts behind each mean, and Pearson correlation across checkpoints separately for each trait. Also retain per-prompt joined rows for plots and audit.
5. If multiple training seeds are run, report seed-level checkpoint summaries and do not count prompts or seeds as independent training datasets. Show category/version points and describe uncertainty at the category level; there are only five categories.

## Interpretation and outputs

A positive association means checkpoints with larger activation shifts also tend to show larger score changes under this evaluation. It is an association, not evidence that the activation shift causes the behavior change. Keep all 15 category/version outcomes visible, including zero or negative shifts. Save joined rows, checkpoint summaries, correlations, and metadata under `results/E09/`; metadata must identify base/checkpoint revisions, source E01 vector IDs, layer convention, prompt set, judge/rubric, and exact join counts.

The pure aggregation contract is `analyze_e09(projection_rows, behavior_rows)` in `src/persona_repro/analysis.py`. Projection rows use `trait`, `checkpoint_id`, `prompt_id`, `base_projection`, and `finetuned_projection`; behavior rows use the same three keys plus `base_score` and `finetuned_score`.
