# E11: Prevent persona drift with positive steering during SFT

## Question and mechanism

Does adding a target persona direction during training make the model less likely to acquire that behavior after the intervention is removed? This is paper §5.2 and Appendix D.3/J.3's preventative steering. For a selected one-based block `ℓ`, training forwards use `hℓ ← hℓ + αvℓ`; the coefficient is positive. The hook covers all sequence positions, including prompts and assistant targets, and remains differentiable. Remove it before saving the adapter for ordinary inference and evaluation.

## Paired experiment design

- Start with the same three explicit-trait II datasets as E08: `evil/misaligned_2`, `sycophancy/misaligned_2`, and `hallucination/misaligned_2`. Train separate adapters for the matching trait vectors and layers selected by E02. The comparison is paired ordinary SFT versus E11 from the same base revision, seed, data manifest, example order, tokenization, LoRA initialization seed, optimizer, and one-epoch exposure.
- Use the frozen raw E01 mean-difference vector at the E02 selected layer. Hold vector extraction and layer fixed across training coefficients. Use `α ∈ {0.5, 1.0, 2.0}` and the ordinary SFT adapter as the zero-coefficient control. These coefficients multiply the raw vector; record its norm and the actual injected norm in metadata.
- Use all 1,000 training groups and 100 development groups per version after the common 200-group pilot. Apply the same assistant-only token labels, non-thinking template, rs-LoRA settings, max length, and seed as E08. Do not mix E10 inference hooks into training.
- After each run, save the adapter with no active steering hook. Evaluate only the unsteered adapter at test time. Any inference-time intervention would confound the preventative effect.

The first phase is three trait-data × matching-trait combinations × three positive coefficients, plus their shared E08 zero controls. If E08 development results show drift on `insecure_code/II` or `mistake_opinions/II`, add a second phase with one affected trait at a time and the same coefficient grid. Use Normal versions only as benign controls at one development-selected coefficient per trait. Do not run the full 15 datasets × 3 traits Cartesian product.

## Outcomes and interpretation

On the held-out 10 questions per trait, use 10 paired rollouts and `gpt-5.6-luna` with upstream trait and coherence rubrics, no calibration. Measure the target trait and both other traits to detect cross-trait effects. Evaluate the same stratified 1,000-question MMLU subset for every adapter. Compare E11 to its paired E08 adapter on trait scores, coherence, and MMLU; cluster uncertainty by question. Record training loss and exact module targets, and verify each adapter can be loaded after the steering context has exited.

Select a representative coefficient using development questions: minimize the targeted trait score while keeping development-set coherence within 5 points of the matched E08 model. Freeze that choice before final evaluation. MMLU is a held-out capability outcome, not a coefficient-selection signal. If no coefficient meets the coherence constraint, report that preventative steering did not find an acceptable setting. Keep negative or null results and any cross-trait increases in the report.

## Runtime invocation

Use `train --vector VECTOR --layer L --coefficient POSITIVE`; use shared `generate`/`score`/`mmlu` on the saved adapter with no inference steering. See [RUNBOOK](../../runbook.md).

The training entry point is `src/persona_repro/training.py::train_adapter`. Pass the raw E01 vector file, the one-based E02 layer, and a positive coefficient for E11; omit those arguments for the ordinary E08 control.
