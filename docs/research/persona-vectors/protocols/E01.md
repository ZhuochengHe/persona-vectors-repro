# E01: Extract Qwen3.5 persona vectors from paired responses

> Settings are being discussed one experiment at a time; do not launch runs yet.

## Question and source

Can the existing positive and negative trait instructions produce a usable persona direction in Qwen/Qwen3.5-4B? This implements paper §2.1–2.2 and Appendix A.1–A.2, while reusing the frozen prompts, questions, and rubric in `upstream/data_generation/trait_data_extract/{evil,sycophantic,hallucinating}.json`.

## Inputs and fixed defaults

- Model: `Qwen/Qwen3.5-4B`, text-only, non-thinking chat mode. Record the exact model revision and rendered/tokenized prompts.
- Traits: `evil`, `sycophantic`, `hallucinating` (the latter maps to upstream filename `hallucinating.json`).
- Use the first 10 upstream extraction questions (IDs 0–9), first three positive/negative instruction pairs (IDs 0–2), both polarities, and 3 rollouts per cell: 180 responses per trait, 540 across three traits. Keep each question/pair/polarity/rollout association in the response manifest.
- Generate and cache all outputs before scoring. Score with the selected GPT-5.6-Luna judge (`gpt-5.6-luna`) using the upstream trait rubric and upstream coherence rubric. Record the judge ID, rubric text, and direct-score mode. Do not run a separate calibration stage.
- Apply the author implementation's paired filter as the primary reproduction rule: retain positive responses with trait score at least 50 and coherence at least 50, and negative responses with trait score below 50 and coherence at least 50. Preserve rejected rows and rejection reasons. Report retained pair counts; fail vector extraction for a condition with no valid matched pairs.

## Procedure

1. Build paired generation records with `build_extraction_tasks(upstream_dir, trait, rollouts=3, question_ids=list(range(10)), instruction_ids=[0,1,2])`. Preserve the upstream evaluation wrapper (`You are an evil/sycophantic/hallucinating assistant.` for positive instructions; `You are a helpful assistant.` for negative instructions). Stable IDs encode trait, question, instruction pair, polarity, and rollout.
2. Generate with fixed sampling settings across conditions (temperature 1, top-p 1, top-k disabled, repetition penalty 1, one beam, min-new-tokens 1, max-new-tokens 1000); store prompt, token IDs, response, finish reason, seed, and sampling config. Derive per-record random seeds deterministically from the stable ID and a recorded root seed.
3. Score trait expression and coherence independently. Keep refusal and malformed judge results explicit; they cannot silently become numeric zeroes.
4. Reapply filtering by matching question, instruction pair, and rollout across positive and negative sides. Save the matched sample manifest and filtered counts.
5. Under inference mode, compute each layer's mean response-token activation for retained positive and negative responses. Use the documented assistant response mask and block outputs before final normalization; stream sums/counts rather than storing token activations.
6. Save raw mean-difference vectors `mean(pos)-mean(neg)` for all 32 transformer blocks and separately save unit-normalized directions for projection/monitoring. Record layer numbering as paper 1–32 and Python index 0–31. Do not select a final steering layer here; E02 selects it on the development split.

One rollout means one generated response for one fixed question/instruction/polarity condition. There are 10 selected questions per trait, 60 conditions per trait, and 180 responses per trait at 3 rollouts—not 180 distinct questions.

## Outputs and checks

Write immutable response/score manifests, filter summary, per-layer vector tensors, and metadata under `results/E01/{trait}/` (or the runtime's configured run root). Metadata must include source commit `b8e0f044fe2410a6fad579f38324f03f13b4e917`, asset hashes, model revision, extraction mask, score mode, filter rule, and vector norms. Check vector shape `(32, 2560)`, finite values, nonzero norms, positive/negative retained counts, and successful hook removal. Report each trait separately and do not treat rollouts as independent questions.
