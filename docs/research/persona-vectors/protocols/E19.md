# E19: Test whether training-data projection differences predict behavior shifts

## Question and source

Before finetuning, does the mean projection difference between training answers and Qwen3.5-4B's natural answers to the same prompts predict the behavior change after E08? This follows paper §6.1 and Appendix F. The scope is the five fixed training categories, three versions per category, and the `evil`, `sycophantic`, and `hallucinating` directions.

## Inputs and fixed defaults

- Use exactly the question-group train subsets that E08 actually optimized on: 1,000 question groups per category, shared across `normal`, `misaligned_1`, and `misaligned_2`. Exclude the 100 dev groups and any filtered, truncated, or otherwise skipped training row; the projection table must describe the actual optimized examples.
- Use the base Qwen3.5-4B checkpoint and frozen unit directions from E01 at the E02-selected layer. E19 features are computed before finetuning; do not use adapted weights or post-finetuning responses to construct predictors.
- For every dataset answer, compute its assistant-response projection with the documented response-token mask. Generate one natural base-model response to the exact same serialized prompt and compute its response-token projection with the same mask. Use deterministic greedy generation and persist token IDs, truncation, and completion status.
- Pair records with `(trait, model_id, vector_id, prompt_id)`, where `prompt_id` identifies the exact shared rendered prompt/question group. The natural response cache can be reused across dataset versions only if those prompt IDs and model/vector identities match exactly.
- Reuse E08 behavior changes (`finetuned_score - base_score`) for the corresponding category/version/checkpoint and trait. Judge with `gpt-5.6-luna` and the same fixed rubric; no separate calibration stage.

## Procedure

1. For each category/version/trait/prompt, save the training-answer projection. Save the paired base natural-answer projection keyed by the same model, vector, trait, and prompt ID.
2. Require exact prompt-key pairing for every represented model/vector/trait. Reject duplicate prompt records, missing natural responses, unmatched natural prompts for represented model/vector/trait combinations, and non-finite projections. Do not compute means from partial joins.
3. For each category/version/trait, calculate `projection_difference = mean(dataset_projection) - mean(natural_projection)` over the paired training subset. Keep both component means, sample count, and source IDs.
4. Join those summaries one-to-one with E08 behavior summaries by `(category, version, trait)`. Fail if a dataset outcome is missing or duplicated. Compute Pearson correlation between projection difference and behavior change separately for each trait across the 15 category/version outcomes.
5. Plot all points with categories distinguished and versions visible. Because the three versions within a category and the three traits share data/model structure, report category-clustered uncertainty and avoid treating 15 outcomes as fully independent. State that five categories provide limited evidence about new domains.

## Interpretation and outputs

The predictor estimates how much the training answers differ from the model's own response tendency along a trait direction. A positive relationship with post-finetuning behavior change supports pre-finetuning screening within these data; it does not establish generalization to arbitrary corpora. Preserve all category/version points and any negative relationships. Save paired prompt projections, dataset summaries, behavior joins, correlations, and metadata under `results/E19/`. Record the actual E08 optimized sample IDs, base model revision, E01 vector IDs, layer and mask definitions, natural-generation settings, judge/rubric, and mismatch counts.

The pure aggregation contract is `analyze_e19(dataset_projection_rows, natural_projection_rows, behavior_rows)` in `src/persona_repro/analysis.py`. Dataset rows use `category`, `version`, `trait`, `model_id`, `vector_id`, `prompt_id`, and `dataset_projection`; natural rows use `trait`, `model_id`, `vector_id`, `prompt_id`, and `natural_projection`; behavior rows use `category`, `version`, `trait`, `base_score`, and `finetuned_score`.
