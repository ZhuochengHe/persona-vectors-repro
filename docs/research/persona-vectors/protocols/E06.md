# E06: Monitor system-prompt-induced trait shifts before generation

## Question and source

Does the last prompt-token activation projected onto an E01 persona direction predict the trait expressed in the subsequent response? This follows paper §3.3, Figure 4, and Appendix C.2–C.3. The monitoring prompts are transcribed verbatim from the local arXiv v3 text at C.3 into `assets/monitoring_prompts.json`; the asset records this provenance and preserves the eight numbered conditions per trait.

## Inputs and fixed defaults

- Base `Qwen/Qwen3.5-4B`, non-thinking text mode, and the three E01 unit directions (`evil`, `sycophantic`, `hallucinating`). Use the same pre-final-normalization block output convention as E01.
- Use 7 questions per trait, sampled with seed 0 from the existing 10-question E02 held-out split before E06 scores are seen, and all eight C.3 prompts. Exact IDs are frozen in `configs/e06.json`. Every condition contains the same questions.
- Generate 4 responses per prompt/question condition (8 × 7 × 4 = 224 responses per trait; 672 across all three traits). Use common sampling settings and paired deterministic rollout seeds across prompt conditions. Save exact rendered prompts and token IDs.
- Score with GPT-5.6-Luna (`gpt-5.6-luna`) and the upstream trait rubric. No separate calibration stage. Keep direct scores and refusals identifiable.

## Procedure

1. Build the 8-prompt by question by rollout matrix using `build_monitoring_tasks(upstream_dir, trait, question_ids, monitoring_path, rollouts=4)`.
2. Before decoding any answer, run a prompt-only forward pass and capture the activation at the final non-padding prompt token from every block. Project each activation onto the corresponding frozen E01 unit vector. Keep prompt-token projection records keyed by sample ID.
3. Generate each answer from exactly the same serialized prompt used for the prompt-only pass. Score the answer for the target trait and retain all judge outputs.
4. First average rollout trait scores for each prompt/question. Report Pearson correlation between projection and that mean score across prompt/question points (overall), plus the mean of the eight separately computed within-prompt correlations, excluding conditions whose score standard deviation is below 1 as in paper C.2. A pooled group-demeaned correlation is an additional diagnostic, not a substitute for the paper statistic. Also report per-condition mean projections and scores, condition-level plots, question-clustered uncertainty, refusal/invalid counts, and sample count.
5. For comparison, show the paper's reported correlations (Table 2) as context only; do not set a pass threshold from them. Since questions are fixed across prompt conditions, cluster uncertainty by question and preserve the paired structure.

## Interpretation and outputs

The overall association includes the large shift between prompt conditions. The within-prompt association asks whether projection tracks finer response differences among questions/rollouts under a fixed condition. Report both even if they diverge; neither correlation establishes causality. Save prompt-level projections, response scores, condition summaries, and correlations under `results/E06/{trait}/`. Include the system prompt asset hash, E01 vector revision, layer, model revision, Luna judge ID, and final prompt token definition. Also report all-layer curves if the runtime captures all 32 layers; the preselected E02 layer is the primary direction for the confirmatory summary.

## Dependency integration

E06 can depend on the final successful E02 stage (`test-score`). Read per-trait layers only from E02 `selection.json`; use frozen E01 vectors and the base checkpoint, without injecting a steering vector. Skip traits with no acceptable E02 development setting, recording the reason. Do not retune the layer using E06 scores or E02 held-out results. Projection is computed once per unique prompt/question before generation and shared across its rollouts. Refusal/invalid scores remain explicit and are excluded from numeric correlations with coverage reported. Analyze each trait separately because layer and vector identity can differ. The approved budget is 7 questions × 4 rollouts × 8 conditions × 3 traits = 672 responses and 672 target-trait judge calls. Compute 168 unique prompt-only projections, capturing all 32 layers in one forward per prompt. E02-selected layers are primary; other layers remain exploratory and never replace the selected layer based on E06 scores. Only target-trait scores are requested; coherence is not a separate E06 endpoint.

Runtime stages: `python -m persona_repro.e06 smoke|generate|score --run <run>`, via `scripts/e06_stage.slurm`. Scoring writes per-trait results and a combined `summary.json`, with question-cluster bootstrap intervals for overall correlation, nonnumeric counts and per-prompt/question numeric rollout coverage.
